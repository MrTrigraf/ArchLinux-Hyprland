## 📌 Предварительные требования

- Установлены `git` и `openssh`:

  ```bash
  sudo pacman -S git openssh
  ```

- Есть аккаунт на GitHub
- Подключение к сети активно

> 💡 `git` и `openssh` не входят в базовый pacstrap-набор гайда [Установка Arch Linux](Arch_linux_install.md) — система устанавливается минимальной. Эти пакеты ставятся только если ты работаешь с git-репозиториями.

## 1. Проверка существующих ключей

```bash
ls -la ~/.ssh/ 2>/dev/null
```

- Если папка **пуста или не существует** — переходим к [генерации](#2-генерация-ключа).
- Если внутри уже есть `id_ed25519` / `id_rsa` — можно использовать существующий ключ (его публичную часть `*.pub` сразу копируем на [шаг 3](#3-просмотр-публичного-ключа)).

## 2. Генерация ключа

Используем алгоритм **`ed25519`** — современный, быстрее и безопаснее RSA, короткие ключи.

```bash
ssh-keygen -t ed25519 -C "ваш_комментарий"
```

### Флаги

| Флаг | Назначение |
|---|---|
| `-t ed25519` | Тип ключа |
| `-C "..."` | Комментарий — метка для опознания ключа в списке на GitHub. Не влияет на безопасность. Удобно указывать `пользователь@машина`. |

### Интерактивные вопросы

| Запрос | Что отвечать |
|---|---|
| `Enter file in which to save the key` | **Enter** (дефолт: `~/.ssh/id_ed25519`) |
| `Enter passphrase` | **Enter** (пустая) или ввести пароль |

> 💡 **Passphrase или нет?**
> - **Пустая** — ключ работает без ввода пароля, удобно для личной машины.
> - **С passphrase** — каждый раз спрашивает пароль (или один раз за сессию через `ssh-agent`).

### Результат

После генерации появятся два файла:

| Файл | Что это |
|---|---|
| `~/.ssh/id_ed25519` | 🔒 **Приватный ключ** — никому не показывать, не коммитить, не выкладывать |
| `~/.ssh/id_ed25519.pub` | 🌐 **Публичный ключ** — отдаём на GitHub |

## 3. Просмотр публичного ключа

```bash
cat ~/.ssh/id_ed25519.pub
```

Вывод — одна строка вида:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIE... ваш_комментарий
```

**Копируем её целиком** — от `ssh-ed25519` до комментария включительно.

## 4. Добавление ключа в GitHub

1. Открыть [github.com/settings/keys](https://github.com/settings/keys)
2. Нажать **New SSH key** (зелёная кнопка в правом верхнем углу)
3. Заполнить поля:

| Поле | Значение |
|---|---|
| **Title** | Название для опознания, например `ArchLinux laptop` |
| **Key type** | `Authentication Key` (оставить по умолчанию) |
| **Key** | Вставить полную строку из [шага 3](#3-просмотр-публичного-ключа) |

4. Нажать **Add SSH key** (может попросить пароль от аккаунта)

## 5. Проверка соединения

```bash
ssh -T git@github.com
```

Первый запуск спросит:

```
The authenticity of host 'github.com (...)' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Отвечаем `yes`. Отпечаток GitHub запишется в `~/.ssh/known_hosts`, больше спрашивать не будет.

### Ожидаемый успешный ответ

```
Hi <username>! You've successfully authenticated, but GitHub does not provide shell access.
```

> 💡 Строка `does not provide shell access` — **не ошибка**. GitHub не даёт shell-доступ, только git-операции (push / pull / clone и т.д.).

## 6. Настройка git: имя

Имя и email пишутся в каждый коммит.

```bash
git config --global user.name "Имя"
```

> 💡 Можно поставить реальное имя, ник, что угодно — видно в истории коммитов.

---

## 7. Настройка git: email через no-reply

> ⚠️ **Не используйте реальный email в публичных коммитах.**
>
> Email из `git config` попадает в каждый коммит и виден в публичных репозиториях **навсегда**. GitHub даёт приватный no-reply адрес, привязанный к аккаунту, но не раскрывающий реальный email.

### Получение no-reply адреса

1. Открыть [github.com/settings/emails](https://github.com/settings/emails)
2. Включить **Keep my email addresses private**
3. Скопировать строку вида `12345678+github@users.noreply.github.com`

> 💡 Числовой префикс у каждого свой.

### Установка email

```bash
git config --global user.email "12345678+github@users.noreply.github.com"
```

---

## 8. Проверка результата

```bash
git config --global --list | grep user
```

### Ожидаемый вывод

```
user.name=ваше_имя
user.email=12345678+github@users.noreply.github.com
```

## ✅ Готово

SSH-ключ настроен, git привязан к GitHub через приватный email. Теперь можно клонировать репозитории через SSH:

```bash
git clone git@github.com:<username>/<repo>.git
```

> 🎉 **Готово к работе с приватными репозиториями и push'ам в публичные.**
