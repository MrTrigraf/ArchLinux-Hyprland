###### Настройка SSH-ключа и подключение к GitHub

> Часть процесса первичной настройки Arch Linux после установки базовых пакетов.
> Цель — сгенерировать SSH-ключ, привязать его к GitHub-аккаунту и настроить git
> для коммитов с приватным email.

Предварительные требования
- Установлен `git` (входит в [[Шаг 1 — Базовые пакеты системы]])
- Есть аккаунт на GitHub
- Подключение к сети активно

1. Проверка существующих ключей

```bash
ls -la ~/.ssh/ 2>/dev/null
```
Если папка пуста или не существует — переходим к генерации.
Если внутри уже есть `id_ed25519` / `id_rsa` — можно использовать существующий
ключ (его публичную часть `*.pub` сразу копируем на шаг 4).

2. Генерация ключа
Используем алгоритм `ed25519` — современный, быстрее и безопаснее RSA, короткие ключи.

```bash
ssh-keygen -t ed25519 -C "ваш_коментарий"
```

Флаги:
- `-t ed25519` — тип ключа
- `-C "..."` — комментарий, метка для опознания ключа в списке на GitHub.
  Не влияет на безопасность. Удобно указывать `пользователь@машина`.

Интерактивные вопросы:
- **Enter file in which to save the key** → Enter (дефолт `~/.ssh/id_ed25519`)
- **Enter passphrase** → пустая (Enter дважды) или с паролем по желанию
  - Пустая — ключ работает без ввода пароля, удобно для личной машины
  - С passphrase — каждый раз спрашивает пароль (или один раз за сессию через `ssh-agent`)

После генерации появятся два файла:
- `~/.ssh/id_ed25519` — **приватный ключ** (никому не показывать, не коммитить, не выкладывать)
- `~/.ssh/id_ed25519.pub` — **публичный ключ** (его и отдаём на GitHub)
 
 3. Просмотр публичного ключа
```bash
cat ~/.ssh/id_ed25519.pub
```
Вывод — одна строка вида:
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIE... 
Копируем её целиком — от `ssh-ed25519` до комментария включительно.

4. Добавление ключа в GitHub
5. Открыть <https://github.com/settings/keys>
6. Нажать **New SSH key** (зелёная кнопка в правом верхнем углу)
7. Заполнить:
   - **Title** — название для опознания, например `ArchLinux laptop`
   - **Key type** — `Authentication Key` (оставить по умолчанию)
   - **Key** — вставить полную строку из шага 3
4. **Add SSH key** — подтвердить (может попросить пароль от аккаунта)
5. Проверка соединения с GitHub
```bash
ssh -T git@github.com
```
Первый запуск спросит:
The authenticity of host 'github.com (...)' can't be established. Are you sure you want to continue connecting (yes/no/[fingerprint])?
Отвечаем `yes`. Ключ-отпечаток GitHub запишется в `~/.ssh/known_hosts`,
больше спрашивать не будет.

Ожидаемый успешный ответ:
Hi "username"! You've successfully authenticated, but GitHub does not provide shell access.
Строка "does not provide shell access" — не ошибка, GitHub не даёт shell,
только git-операции.

 6. Глобальная настройка git
Имя и email пишутся в каждый коммит.
Имя
```bash
git config --global user.name "Имя"
```
Можно поставить реальное имя, ник, что угодно — видно в истории коммитов.

 7. Email (через приватный no-reply)
> **Не используйте реальный email в публичных коммитах.**
> Email из `git config` попадает в каждый коммит и виден в публичных
> репозиториях навсегда. GitHub даёт приватный no-reply адрес,
> привязанный к аккаунту, но не раскрывающий реальный email.

8. Получение no-reply адреса:
Открыть <https://github.com/settings/emails>
Включить **Keep my email addresses private**
Скопировать строку вида `12345678+github@users.noreply.github.com`
Установка:
```bash
git config --global user.email "12345678+github@users.noreply.github.com"
```
(числовой префикс у каждого свой)

9. Проверка результата
```bash
git config --global --list | grep user

Ожидаемый вывод:
user.name=ваше_имя
user.email=12345678+github@users.noreply.github.com
