# 💽 Монтирование дополнительного диска

Инструкция по подключению отдельного SSD (например, под игры) с автоматическим
монтированием через `/etc/fstab`. Идентификация раздела — **строго по UUID**
(в системе несколько дисков, метки LABEL могут совпасть).

> ⚠️ **Внимание:** форматирование безвозвратно стирает все данные на диске.
> Убедись, что выбран правильный диск, прежде чем выполнять `wipefs` и `mkfs`.

> 📝 **Про обозначения `<диск>` и `<раздел>`:** в командах ниже это
> **плейсхолдеры**, а не реальные имена. Подставляй свои значения из вывода
> `lsblk`. Диск — это всё устройство (например `/dev/sdb`, `/dev/nvme1n1`),
> раздел — конкретный кусок на нём (например `/dev/sdb1`, `/dev/nvme1n1p1`).
> У NVMe-дисков раздел обозначается с `p`: диск `/dev/nvme1n1` → раздел
> `/dev/nvme1n1p1`.

## ext4 или btrfs?

**ext4** — проверенная временем журналируемая файловая система, стандарт де-факто
в мире Linux. Она нетребовательна, отличается стабильной и предсказуемой
производительностью на случайных операциях и практически не нуждается в
обслуживании. Снапшоты и прозрачное сжатие не поддерживает — это плата за
простоту.

**btrfs** — современная файловая система с механизмом copy-on-write, которая
приносит снапшоты, подтома (subvolumes) и прозрачное сжатие «из коробки». За
гибкость приходится платить чуть большими накладными расходами и вниманием к
нюансам настройки.

**Что выбрать:** для чисто игрового диска рекомендуется **ext4** — она проще,
быстрее на случайном доступе и не требует настройки; игровые ассеты уже сжаты,
поэтому выигрыш от сжатия btrfs минимален, а снапшоты для игр обычно не нужны.
Бери **btrfs**, если хочешь снапшоты состояния или прозрачное сжатие данных.

## Порядок действий

### 1. Определить диск

```bash
lsblk -f
```

Найди нужный диск по размеру и запомни его имя (`<диск>`) и имя раздела, который
создашь на следующих шагах (`<раздел>`).

### 2. Очистить диск

```bash
sudo wipefs --all /dev/<диск>
```

### 3. Создать раздел

```bash
sudo cfdisk /dev/<диск>
```

В интерактивном меню: выбери разметку **GPT** → `New` (создать раздел на весь
объём) → `Write` (подтвердить вводом `yes`) → `Quit`.

### 4. Отформатировать раздел

Выбери **один** вариант в зависимости от файловой системы. Флаг `-L Game` задаёт
метку сразу при форматировании:

```bash
# ext4
sudo mkfs.ext4 -L Game /dev/<раздел>

# btrfs
sudo mkfs.btrfs -f -L Game /dev/<раздел>
```

> 💡 **Альтернатива:** если метку нужно задать или изменить отдельно (например,
> `-L` не сработал или хочешь переименовать позже), используй:
> ```bash
> # ext4
> sudo e2label /dev/<раздел> Game
> # btrfs (раздел должен быть смонтирован; <точка> — точка монтирования)
> sudo btrfs filesystem label <точка> Game
> ```

### 5. Создать точку монтирования

```bash
sudo mkdir -p /disks/game
```

> Cтандартные пути монтирования:
>
> - `/media/`
> - `/mnt/`
> - `/run/media/<user>/`

### 6. Узнать UUID раздела

```bash
sudo blkid /dev/<раздел>
```

Скопируй значение `UUID="..."` (без кавычек).

### 7. Прописать в `/etc/fstab`

```bash
sudo vim /etc/fstab
```

Добавь в конец файла **одну** строку под свою файловую систему (подставь свой
UUID из предыдущего шага):

```
# ext4
UUID=<твой-uuid>  /disks/game  ext4   defaults,noatime  0 2

# btrfs
UUID=<твой-uuid>  /disks/game  btrfs  rw,noatime,compress=zstd:1,ssd,discard=async,space_cache=v2,nodev,nosuid  0 0
```

Пояснения к полям: `noatime` — не обновлять время последнего доступа к файлам
(меньше износ SSD и быстрее); для btrfs `compress=zstd:1` — лёгкое сжатие,
`ssd`/`discard=async` — оптимизации под SSD; последнее поле (fsck) для ext4 = `2`
(проверять после корневого раздела), для btrfs = `0` (btrfs не использует
традиционный fsck при загрузке).

> 💡 **Отображение в файловом менеджере.** Если хочешь, чтобы диск был виден в
> боковой панели GNOME Files (Nautilus) рядом с другими дисками, добавь в опции
> монтирования `x-gvfs-show`. Работает для любой файловой системы (и ext4, и
> btrfs). Просто допиши `,x-gvfs-show` к списку опций своей строки, например:
>
> ```
> # ext4
> UUID=<твой-uuid>  /disks/game  ext4   defaults,noatime,x-gvfs-show  0 2
>
> # btrfs
> UUID=<твой-uuid>  /disks/game  btrfs  rw,noatime,compress=zstd:1,ssd,discard=async,space_cache=v2,nodev,nosuid,x-gvfs-show  0 0
> ```
>
> Без этой опции диск на путях вроде `/mnt` или `/disks` в панель не попадёт —
> дело не в самом пути, а именно в `x-gvfs-show`. После правки перезапусти
> Nautilus (`nautilus -q`), а если не появился сразу — перелогинься.

### 8. Проверить ДО перезагрузки

```bash
sudo systemctl daemon-reload
sudo mount -a
mount | grep game
```

Если `mount -a` отработал без ошибок и последняя команда показала раздел —
`fstab` корректен. **Если появилась ошибка — исправь `fstab` сейчас**, не
перезагружаясь: ошибка в `fstab` может уронить загрузку в аварийную консоль
(emergency shell).

### 9. Перезагрузиться

```bash
reboot
```

### 10. Отключение запроса пароляы

По умолчанию новый раздел принадлежит `root`, и запись в него потребует `sudo`.
Чтобы работать с диском без повышения прав, смени владельца.

Сначала узнай своё имя пользователя и основную группу (если забыл):

```bash
whoami      # имя пользователя
id -gn      # основная группа
groups      # все группы, в которых состоишь
```

Затем смени владельца (подставь свои `имя:группа`):

```bash
sudo chown -R <имя>:<группа> /disks/game
```

## Проверка после перезагрузки

```bash
mount | grep game     # раздел смонтирован
lsblk -f              # видно метку Game и точку монтирования
```

Готово — диск монтируется автоматически при каждой загрузке.
